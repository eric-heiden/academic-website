SHAC with MuJoCo Warp

Newton experiments coupling SHAC-style differentiable policy optimization to the MuJoCo Warp differentiability branch. The latest pass stages the problem through acrobot target control, free-body control, sphere/capsule contact targets, Hopper, Cheetah, and Ant. The newest MJWarp fix changes differentiable kinematics from branch replay to level-order replay, removing duplicated ancestor adjoints in branched bodies. Cheetah now trains with SHAC using Newton contacts and moves 18.44 m over an 8 s rollout. Hopper still does not produce a reliable hopping policy: default rewards select standing, while progress-emphasis rewards select fast falling. Ant remains the final unsolved target.

What Is Fixed

The MJWarp gradient path now includes fixes for free-joint kinematics replay, dense mass-solve VJPs, RNE qfrc_bias/cfrc_int adjoints, in-place state output isolation in _advance, and repeated root writes in com_vel. This update adds active contact-row aref/D VJPs, contact-row position gradients for all pyramidal rows, contact buffer isolation, and the missing quadratic-row efc.J force-law term. The latest fix computes differentiable kinematics once per body level instead of replaying body_branches; this removes the duplicated root-pitch gradient in branched planar bodies and drops Cheetah no-contact state/action error to 6.4e-5.

What Is Not Fixed

Contact-rich state finite differences are still discontinuous for MuJoCo contacts, and Hopper is not solved as a task. The current Hopper one-step gradients are clean, so the failure now looks like a SHAC optimization/reward issue rather than the earlier obvious VJP bug. Cheetah/Newton contacts are a useful stepping stone: one-step state/action error is 1.0e-4 and training learns fast forward motion, but long rollouts still hit invalid resets after aggressive speeds.

Code Findings

The most important MJWarp fixes were not contact-specific. First, free-joint kinematics were recomputed once per branch, corrupting qpos gradients for floating roots. Second, dense mass assembly had no useful generated adjoint for the dense matrix path used by the solve. Third, RNE force accumulation needed explicit adjoints for cfrc_int, cinert, cdof, and related kinematic intermediates. Fourth, _advance had to isolate output qpos/qvel arrays under AD to avoid overwriting saved inputs. Fifth, Newton's free-joint force route writes to MJWarp xfrc_applied; the support.apply_ft map into qfrc_smooth needed an explicit VJP for free-root force controls. The active-limit drilldown now shows that the solver mass correction's matrix gradient is algebraically right, but the dense diagonal M00 adjoint over-injects through the parent cdof path.

SHAC Findings

The harness had its own bug: early terminal falls still bootstrapped from the critic. DiffRL sets the terminal value to zero for early termination. Matching that behavior, and making terminal fall reward a fixed negative value, removes the high-speed crash exploit. The new upright gate also rejects the rolled-over progress policy. The remaining failure is not a simple one-step gradient sign bug; it appears when the task trades long-horizon progress against repeated Ant contacts and active joint limits. The simple sphere/capsule scenes now check out, and the no-limit Ant decomposition is accurate again after the RNE fixes, but limit-enabled Ant still inherits the dense mass-diagonal residual and SHAC currently reaches only a stable crawl.

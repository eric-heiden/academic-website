SHAC with MuJoCo Warp

Newton experiments coupling SHAC-style differentiable policy optimization to the MuJoCo Warp differentiability branch. The latest pass stages the problem through acrobot target control, free-body control, sphere/capsule contact targets, Hopper, Cheetah, and Ant. The newest MJWarp fix removes duplicate auto-AD through the RNE qfrc_bias/cfrc_int path, so free-fall mass/bias VJPs cancel correctly and Hopper/Ant one-step state gradients match finite differences again. Cheetah now has a clean SHAC stepping-stone result with MuJoCo contacts at substep 1: 10.33 m forward over 480 frames with zero falls/invalids. PPO verifies that the 16-substep Cheetah task itself is learnable. The runner now also records Newton/MJWarp revisions, writes live history JSON, loads PPO checkpoints into SHAC actors, spaces replicated Newton-contact worlds apart, and renders policy videos through a shared smoothed follow camera. Ant now uses Isaac-style local observations/reward terms and joint-order effort mapping to match IsaacLab's wildcard joint order; MuJoCo actuator-order mapping remains available for DiffRL/MuJoCo comparisons. The report runner now records Ant contact friction and joint damping, and actually applies the advertised ant_height_weight in the Isaac-style reward path. The strongest Ant baseline now uses IsaacLab physical constants, force scale 10, progress reward weight 2, a larger terminal fall penalty, strict full-horizon selection, and a small height reward. Deterministic videos are stable, but randomized-start 1024-env Ant replays expose rare falls that single deterministic replays hid. PPO typically moves about 10.5 m over 480 randomized frames. SHAC warm-started from that actor can improve small-batch selection, but 1024-env stochastic checkpoint selection rejects those updates and keeps the PPO warm start as the best robust policy. Hopper is now solved as a stepping-stone: a DiffRL-exact PPO run reaches 14.49 m over 480 frames, and SHAC warm-started from that no-LayerNorm PPO actor selects a zero-fall 14.49 m rollout before longer short-horizon updates drift into falls.

What Is Fixed

The MJWarp gradient path now includes fixes for free-joint kinematics replay, dense mass-solve VJPs, RNE qfrc_bias/cfrc_int adjoints, in-place state output isolation in _advance, and repeated root writes in com_vel. This update adds active contact-row aref/D VJPs, contact-row position gradients for all pyramidal rows, contact buffer isolation, and the missing quadratic-row efc.J force-law term. The latest fix computes differentiable kinematics once per body level instead of replaying body_branches; this removes the duplicated root-pitch gradient in branched planar bodies and drops Cheetah no-contact state/action error to 6.4e-5. The newest cinert adjoint hook improves Ant H=2 policy finite differences from 3.5e-1 to 1.3e-1 and Cheetah/MuJoCo policy finite differences to 1.1e-2. The newest RNE fix replaces auto-backward through qfrc_bias with an explicit adjoint and disables auto-backward through the cfrc tree accumulation; Hopper no-limit smooth dynamics now has 2.7e-4 full state/action error and Ant H=5 one-step state/action error is 8.1e-5. On the harness side, Newton-contact vectorized environments now use nonzero world spacing, PPO checkpoints can warm-start SHAC actors, Ant actions can follow either IsaacLab-like joint order or MuJoCo actuator order, the Isaac-style Ant height reward now uses ant_height_weight, checkpoint selection can include forward displacement, initial PPO warm starts are evaluated and saved before any SHAC update, and SHAC selection can now run on a separate large randomized environment batch via --selection-num-envs. SHAC can also use a no-LayerNorm actor architecture that exactly matches PPO checkpoints. Hopper stochastic resets are clamped inside finite joint limits. The newest Newton fix preserves MJCF joint anchor positions per expanded DOF; this fixes Hopper's root slide/hinge anchors when SolverMuJoCo exports merged Newton joints back to MuJoCo and when it refreshes the MJWarp runtime model. Every run records the imported Newton and MJWarp commits in its JSON artifact.

What Is Not Fixed

Hopper is solved for PPO and SHAC warm-start selection, but not for long unconstrained SHAC continuation: after epoch 2, the 32-step differentiable objective increases short-horizon reward while the 480-step selected rollout accumulates falls. The Gym-style Hopper reward remains a negative control for this DiffRL asset. Ant now moves much farther under IsaacLab physical settings, but the gait is still a low crawl rather than a tall natural walk. A faster 12-13 m Ant policy exists, but randomized 1024-env replays expose rare falls, so it is kept as a diagnostic rather than the headline result. Adding a small height reward improves the Ant score but does not fully change the low-crawl gait. SHAC still needs strict full-horizon checkpoint selection: with 1024 randomized selection envs, both 5e-6 and 1e-6 actor-learning-rate SHAC continuations were rejected because they either introduced rare falls or did not beat the PPO warm start.

Code Findings

The most important MJWarp fixes were not contact-specific. First, free-joint kinematics were recomputed once per branch, corrupting qpos gradients for floating roots. Second, dense mass assembly had no useful generated adjoint for the dense matrix path used by the solve. Third, RNE force accumulation needed explicit adjoints for cfrc_int, cinert, cdof, and related kinematic intermediates. Fourth, _advance had to isolate output qpos/qvel arrays under AD to avoid overwriting saved inputs. Fifth, Newton's free-joint force route writes to MJWarp xfrc_applied; the support.apply_ft map into qfrc_smooth needed an explicit VJP for free-root force controls. The latest Hopper free-fall drilldown showed the key cancellation bug: CPU MuJoCo and MJWarp both produce pose-independent free-fall acceleration, but AD still injected root-angle and joint-position gradients. Finite-difference decomposition showed the dense M VJP was correct; the residual came from leaving Warp auto-AD active through qfrc_bias = dot(cdof, cfrc) and the cfrc tree accumulation while also recording the custom RNE adjoint. The fix disables those auto-backward kernels and records an explicit qfrc_bias adjoint that routes cdof.grad and cfrc_total.grad exactly once. The latest Newton-side Hopper bug was an importer/exporter mismatch: MJCF can define multiple scalar root joints on one body with distinct joint pos anchors, while Newton merges them into one D6-style joint. SolverMuJoCo was exporting every expanded MuJoCo joint with the merged child transform position, and the runtime mjw_model.jnt_pos refresh repeated the same mistake. A new per-DOF mujoco:dof_jnt_pos attribute now preserves those anchors through import, export, and MJWarp data refresh.

SHAC Findings

The harness had its own bug: early terminal falls still bootstrapped from the critic. DiffRL sets the terminal value to zero for early termination. Matching that behavior, and making terminal fall reward a fixed negative value, removes the high-speed crash exploit. The new upright gate also rejects the rolled-over progress policy. The remaining failure is no longer a simple smooth-dynamics gradient bug: Hopper and Ant short-horizon state/action checks now pass, but SHAC training still trades progress against repeated contacts and active limits poorly. Hopper with limits on is nonsmooth at reset because the thigh and leg joints start on their upper stops; reset noise is now clamped back inside finite limits, and the new inside-limit start-pose probe confirms this was a real harness bug. It did not solve hopping: Gym-style reward, upright warm-start curriculum, and inside-limit progress PPO all still become falling policies under the 480-step selection score. Cheetah remains the clean success case, and PPO verifies the faithful 16-substep Cheetah environment. Ant needed two environment fixes beyond the MJWarp adjoints: local Isaac-style observations/reward terms and MuJoCo actuator-order torque mapping. A later report-runner bug was that the Isaac-style reward accepted --ant-height-weight but ignored it; the current runners now add a dense torso-height reward and can checkpoint by reward plus forward displacement. With those fixes, PPO produces a better movement waypoint (3.99 m, mean up 0.96), but the policy is mostly sideways and still has 7 fall events. SHAC warm-started from that PPO checkpoint does not fix the gait: its best strict checkpoint has zero falls and 2.96 m displacement, but mean heading is -0.69. The earlier SHAC curriculum still moves farther (7.57 m) but has fall events and a low crawl. A separate up > 0.85 PPO selector proves the renderer/reward can reject rolling postures, but it selects a stationary tripod stance with -0.06 m displacement. Matching IsaacLab's larger PPO network family and disabling observation RMS improves long-horizon stability under up > 0.7, but still selects stationary stances; progress warm-start reaches only 0.10 m before later updates regress. The missing piece is now a curriculum/objective that preserves upright height and heading while increasing progress, plus better long-horizon contact/limit optimization. It no longer looks like a single RNE mass/bias cancellation bug.

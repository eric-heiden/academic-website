Cartpole Fix

The first cartpole run loaded the DiffRL URDF directly into a Y-up Newton model. DiffRL actually applies a -pi/2 rotation about X before setting the pole joint to -pi. Without that transform, gravity and the pole axis were mismatched, producing the sideways-looking behavior. The Newton harness now applies the same transform.

Ant Diagnosis

The ant MJCF import was missing an explicit ground plane, so both contact backends initially let the ant fall through the world. The ant builder now uses DiffRL's Y-up transform, rest pose, contact material, previous-action observation, early termination, and a Y-up ground plane. The remaining bad-looking gait is consistent with a state-gradient problem rather than a contact-backend choice: finite differences match the one-step action gradient, but not the qpos-driven state transition gradients used by multi-step SHAC.

Implementation Notes

Newton's SolverMuJoCo uses the MJWarp differentiability branch with opt-in gradient-enabled data fields. The harness wraps one Newton/MJWarp step in a PyTorch autograd function: forward runs the solver normally, backward replays the step under a Warp tape and returns MJWarp adjoints to PyTorch.

Status

Cartpole is physically plausible and stabilizes. Ant now has correct ground contact and trains with both MuJoCo contacts and Newton differentiable contacts. The finite-difference checks show that the remaining failure is not specific to MuJoCo contacts versus Newton contacts: qpos-related transition gradients disagree with finite differences even when contacts are disabled, while the immediate action gradient is accurate.

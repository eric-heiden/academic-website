TL;DR

Latest Warp PR #1355 no longer reproduces the scalar RUN_TO_RUN failure: the pure Warp scalar atomic_add repro produced one bit-exact output across 100 reruns after a clean local rebuild. Current Newton main is also bit-exact for mesh inertia in the verification probe, and it no longer relies on scalar wp.atomic_add reductions for this path.

The current report therefore treats V3 tile_sum as the Newton implementation to evaluate. The old V2 benchmark rows from a superseded PR #1355 checkout are removed from all current tables and plots; they are not a valid statement about the latest PR head.

3 · Runtime

V3 is in the same performance class as the old atomic baseline: median per-call overhead is 2.3% relative to V0, while the summed median time over all 262 meshes is -1.3% relative to V0. V1 is deterministic but spends more time moving and reducing per-triangle buffers.

4 · V0 Run-to-Run Inertia Drift

This plot is fixed to use the stored V0 rerun outputs directly. For each mesh, it computes the maximum Frobenius norm difference in the inertia tensor relative to the first rerun. All 262 V0 rows have positive drift; V1 and V3 have stable output hashes on every stored row.

V0 drift spans from 3.70e-16 to 2.12e+05 in this norm. The large end comes from dense meshes where the f32 accumulation order changes the reduction result substantially.

5 · Accuracy Against V1

V3 remains deterministic while keeping the error level below V0 across the robot set. The maximum relative inertia difference vs V1 is 3.02e-05 for V3 and 4.99e-04 for V0.

6 · Memory Footprint

V0 and V3 keep only a constant accumulator per launch. V1 allocates per-triangle buffers and therefore scales with mesh size. V3 gets determinism without paying the per-triangle output-buffer cost.

8 · Implementation Status

Current Newton newton/_src/geometry/inertia.py uses a fixed tile size of 256 and launches store_mesh_inertia_sum through wp.launch_tiled. The kernel reduces the per-triangle contributions with wp.tile_sum, so the mesh inertia path does not depend on scalar f32 wp.atomic_add ordering.

The latest Warp PR #1355 scalar RUN_TO_RUN result is still important: it verifies that the earlier pure Warp repro no longer fails. It is separate from the current Newton result because Newton main has already moved to the V3 tile-sum implementation.
